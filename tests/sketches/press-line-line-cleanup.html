Press-line / stats slab — fix the doubled hairlines

The "AS SEEN IN" strip on Home.jsx sits flush against the .ht-stats-area "14 / 100 / 32" tile. Today the two sections each carry their own top + bottom hairlines in two different border tokens, so the eye reads four parallel rules stacked over 80 px of cream — the doubling the user flagged. Six redesigns that all keep the same content and behaviour, ranked from most conservative (just colour-match the rules) to most decisive (remove the box entirely).

The two hairlines today

rgba(11,15,20,0.20) — cooler, ink-tinted. Used on .ht-press-line top + bottom in style.css:16084.

var(--ht-border-color) = #E2DBCE — warmer, paper-tinted. Used on .ht-stats-area .ht-stats-wrapper top + bottom in style.css:13378.

Same weight (1 px), different colour temperature. On cream they read as two systems, not one.

The stack

From top: press-line top rule (ink) → 22 px → logos → 22 px → press-line bottom rule (ink) → 56 px of .ht-press-line-area padding → 40 px of .ht-stats-area padding → stats top rule (warm) → numbers → stats bottom rule (warm). Four rules in ~250 px.

Both press-line and stats sit inside one bordered slab. Top hairline, mid hairline between logos and numbers, bottom hairline. The mid rule reads as a deliberate row divider rather than a closed-then-reopened box. Editorial register — like a press kit's masthead block.

III

Unified hairline colour — most conservative

Keep the structure identical to today. Only change: swap the press-line's ink-tinted rgba(11,15,20,0.20) for the same --ht-border-color the stats area already uses. Four rules remain but they now read as one consistent system. No JSX change at all.

Unchanged.
Rules

Change
Two-line CSS swap.
Risk
Zero. Strictly cosmetic.

vs today: still four rules, still doubled-up over 80 px, but they're the same colour. Solves the "different lines" half of the user's complaint; doesn't address the "too many" half. Lowest-effort fallback if we want to ship a fix in one PR without touching markup.

/* style.css:16084 */
.ht-press-line {
  border-top:    1px solid var(--ht-border-color);
  border-bottom: 1px solid var(--ht-border-color);
  /* was: rgba(11,15,20,0.20) */

Recommendation — ship I, fall back to III

I (no press-line border) is the cleanest fix for the doubled-rules problem and keeps every other component untouched. III (unify the colour) is the one-line CSS change if we'd rather not lose the press-line frame at all. II and V are larger structural moves worth keeping in mind for the next press-section pass.

Both Home.jsx and About.jsx render the marquee variant of PressLine.jsx, so any CSS change automatically applies to both.
